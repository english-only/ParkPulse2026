## 🚀 PERFORMANCE OPTIMISATIONS

### 1. Trees Layer — Keep Detail, Kill Lag

The `trees.geojson` file is 17MB and causes severe lag. Optimise rendering while keeping all data intact:

- **Keep all tree properties** in the dataset (don't strip anything). Data stays complete for popups and detail views.
- **Use a canvas renderer** for tree markers instead of DOM elements:
  ```js
  const renderer = L.canvas({ padding: 0.5 });
  ```
  Pass `{ renderer }` to each tree marker. Canvas rendering is dramatically faster than SVG/DOM for thousands of markers.
- **Split the tree data into geographic tiles**: Instead of loading all 17MB at once, divide `trees.geojson` into 9 smaller files by grid (NW, N, NE, W, C, E, SW, S, SE). Only load tiles visible in current viewport + 1 adjacent tile. As user pans, load/unload tiles dynamically.
  - File names: `trees-nw.geojson`, `trees-n.geojson`, etc. (~2MB each instead of 17MB monolith)
  - Example bounds for Sydney: NW (-33.6 to -33.8, 150.7 to 150.9), etc.
- **Increase zoom threshold** from 15 to 16 before trees appear — fewer tiles rendered at once.
- **Use `L.circleMarker`** instead of `L.divIcon`. Circle markers with canvas render 10x faster.
- **Lazy-load tree popup details**: When a tree marker is clicked, fetch full details on-demand (show spinner). Don't keep all properties in memory at once.
- **Add visible note** next to Trees filter: "🌳 Renders at zoom 16+ (high detail)"

### 2. Debounce & Throttle Everything

- **Search input**: debounce 300ms before filtering/rendering results
- **Map pan/zoom events**: throttle `invalidateSize()` calls to max 60ms intervals
- **Window resize**: throttle sidebar resize calculations to 16ms (60fps)
- **Filter toggles**: use `requestAnimationFrame` for layer add/remove animations

### 3. Image & Asset Optimisation

- **Favicon**: convert `favicon.svg` to `.ico` (smaller, faster to load)
- **Open Graph image** (`opengraph.jpg`): compress to max 100KB (currently unknown size)
- **Data files**: gzip-compress all JSON/GeoJSON in transit (server should handle, but mention it)
- **Lazy-load park photos** in modals — use `loading="lazy"` attribute on all `<img>` tags

### 4. Bundle Size Analysis

- Check if React, ReactDOM, React Router are being bundled unnecessarily or duplicated
- Remove unused Leaflet plugins if any are included
- Tree-shake unused utility functions from `main.js` and `explore.js`
- Ensure only one copy of Leaflet is loaded (not duplicated)

### 5. Data Loading Strategy

- **Cache all GeoJSON in localStorage** after first load (with expiration: 7 days)
  ```js
  localStorage.setItem('parkpulse_cache_parks', JSON.stringify(data), { expires: 604800 })
  ```
  Check cache before fetching — huge speed boost on repeat visits
- **Show cached data indicator** in UI when serving from cache: "📦 Data cached (tap to refresh)"
- **Preload critical data only** on startup: Parks + Dog Parks + NPWS. Everything else lazy-loads on filter toggle.
- **Show a progress bar** while GeoJSON files load (especially on slow connections)
